## 代码检查发现

以下区分静态确认的实现事实与尚需故障注入验证的影响；测试通过不覆盖这些缺口。

1. **成功 Put 不释放 pool gate 的 pending。** `server.go:Put` 仅在
   `!committed` 时 release，成功后设为 true；`gate.go` 没有另一个
   confirmed 集合或状态转换。成功对象的 pending 标记持续积累。
   现有 `putViaGate` 测试辅助函数复制了同样路径，不能发现这个遗漏。
   接续时在索引提交成功后释放 pending，由已确认索引负责后续冲突检查；
   覆盖普通写入、alias、响应发送失败和重启后的重复写入。

2. **存在性检查并非文档所说的纯内存查找。** `DeviceState.Confirmed`
   调用 `blk.FindLatestIndexEntry`，后者每次分配 4 MiB 缓冲并 ReadAt
   扫描索引；pool gate 在等待结果期间持有全局锁。
   多盘会放大扫描和分配成本。超时只让调用者返回，不取消底层扫描。
   应规划启动重建、提交时更新的每盘已确认索引，并审查锁顺序及 alias
   成对发布；不要以注释中的“RAM-resident”作为已实现的依据。

3. **启动中途失败没有回收先前打开的磁盘。** `NewServer` 在后续设备
   ParseDiskID/OpenDevice 失败时直接返回。应覆盖第二块盘失败时的清理。

4. **zram 自动恢复尚未完整覆盖冷启动。** 当前只遍历旧 pan.json 中的
   设备，`EnsureLoaded` 要求设备路径已经存在；不能据此宣称完成了
   “发现快照、准备设备、刷新映射”的完整启动过程。加载失败跳过设备是
   当前实现策略，需要与启动状态、可观测错误和快照发现行为一起验收。
   默认快照目录为空；移植 CLI 仍有 `.nbss_zram_snapshots` 默认值。

5. **并发测试没有贯穿真实 RPC，且顺序仍依赖 Sleep。** 当前 daemon
   仅 4 个测试，主要直接调用 gate/PreparedWrite；两个竞态测试用
   20ms Sleep 等待首个写入。改用 channel 握手确认预留到位，新增经过
   Server.Put 或本地 gRPC 的测试，避免辅助函数绕开编排缺陷。
   alias 竞态的另一胜者分支还需使用包含尾部跳转字节的合法 payload。

6. **大对象 Get 的已知简化有实际互操作限制。** Get 先读取完整对象，
   再将结果作为一条消息发送，范围读取也先分配全对象。
   本地 grpc v1.83.2 源码的默认客户端接收上限为 4 MiB
   （clientconn.go 的 defaultClientMaxReceiveMessageSize）。超过限制的
   单条响应需要特殊客户端配置；应增加真实 RPC 测试并安排分块发送，
   不能把小对象通过等同于 256 MiB 上限可用。

7. **落盘和失败原子性需独立审查。** OpenDevice 使用普通 O_RDWR，
   写路径未启用 O_DIRECT；Commit 依次 WriteAt alias 和 real entry，
   没有 Sync。不能把当前注释的 durable 当成掉电验证结果。
   第二次索引写入失败后的残留、并发读是否观察到半个 alias pair、
   重启索引扫描对截断/读错误的处理都需要专门复现及契约判断。
   本轮没有复现磁盘故障，不将这些风险描述为已观测数据损坏。

## 里程碑 4 验收矩阵

| 领域 | 必须覆盖的情形 | 优先环境 |
|---|---|---|
| 路由 | 最小可容纳 CHD；无合适盘时最大 CHD 回退；空池/不可容纳 | 临时稀疏文件 |
| zram 分层 | 小于、等于、大于阈值；zram 无空间时回退；仅 zram 池 | 可注入设备分类的单元测试 |
| CHD | 空盘、满盘、pending 占用、abort 释放、commit、重启重建 | 临时稀疏文件 |
| 全池唯一性 | 同 FID；plain/alias；alias/alias；交换先后顺序 | 两盘 + channel 握手 + race |
| RPC 生命周期 | pending 的 Get/Head 为 NotFound；提交后可读；重复写冲突 | 本地 gRPC + 两盘 |
| 回滚 | 短流、超长流、取消、停滞、extent 冲突；FID 和空间可重试 | 本地 gRPC + 故障注入 |
| 多盘读取 | 数据只在第二盘；全盘缺失；一个盘故障另一盘命中 | 两盘及可控故障 |
| 资源 | 初始化部分失败；成功后 pending 清空；超时后台任务退出 | 单元/集成测试 |
| 重启 | 已确认对象和 alias 可读；重启后仍拒绝重复 FID | 关闭再打开临时盘 |
| zram 恢复 | 已加载、冷启动、快照缺失/损坏/ID 不符、部分失败 | 注入测试，最后真实 zram |

测试盘优先沿用 newTestDisk 的稀疏文件方案；补充具有合法 NBSS header、
不同 disk ID 和容量的夹具，以覆盖正式启动路径。普通测试不依赖 USB 盘。
先证明指定对象实际进入不同磁盘，再断言“跨盘测试通过”。
压力测试使用可复现的输入与同步屏障，分别统计合法冲突和非预期错误，
验证成功对象内容、失败对象不可见性及资源回收，不以吞吐数字替代正确性。
